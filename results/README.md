# 统计结果说明

`per-run.csv` 列出每次正式测量的请求数、吞吐量、错误数、平均延迟、P50/P95/P99，以及对应的测量窗口和数据库计数。`summary.csv` 是每档三轮的汇总，吞吐量附样本标准差。各轮百分位先单独计算，再取三轮平均，没有混同为合并百分位。

`analyze.py` 采用最近秩百分位，吞吐量按固定的 60 秒窗口计算。JTL 的 elapsed 单位为毫秒，单请求耗时不足 1 毫秒时可出现 0，均值可低于 1 毫秒。

`html/read-t100-r1/` 与 `html/write-t100-r1/` 是各接口一轮 100 并发的 JMeter 报告，用筛选后的测量 JTL 生成。JMeter 按首尾样本跨度计算吞吐量，与固定 60 秒口径可能有少量尾部差异。HTML 报告的百分位窗口设为 100 万条，覆盖单轮全部样本。

`monitoring/` 保留三个必需指标的 Prometheus query_range 原始 JSON、健康状态和按正式窗口计算的监控统计。采样间隔为 5 秒，CPU 是 1 分钟速率窗口；曲线中也能看到轮次间隔、预热和实验库恢复阶段。
